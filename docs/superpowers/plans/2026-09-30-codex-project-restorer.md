# Codex 项目恢复工具实施计划

**目标：** 构建一个单文件 Windows EXE，安全扫描并恢复 Codex 左侧缺失项目，现有项目优先，保留最近一次备份并支持回滚。

**架构：** Python 标准库负责 SQLite、JSON、备份和原子写入；Tkinter 提供中文界面；PyInstaller 打包单文件 EXE。核心逻辑与界面分离，所有写入行为先在临时样本上测试。

**技术栈：** Python 3.11、Tkinter、sqlite3、unittest、PyInstaller。

**设计：** `docs/superpowers/specs/2026-09-30-codex-project-restorer-design.md`

## 全局约束

- 当前 Codex 项目按规范化名称或路径去重后始终优先。
- 工具不得删除、移动或修改任何项目目录。
- Codex/ChatGPT 进程运行时禁止恢复和回滚。
- 状态写入必须先备份、原子替换并复读验证。
- 成功后只保留最近一次完整备份。
- 运行时仅使用 Python 标准库。

## 实施任务

### 任务 1：项目扫描与合并

- 创建 `tests/test_core.py`，先覆盖历史项目分组、同名跳过、同路径跳过、路径不存在不可恢复和现有数据不变。
- 运行测试并确认因 `core` 模块不存在而失败。
- 创建 `core.py`，实现状态读取、SQLite 只读扫描、规范化与恢复候选计算。
- 运行全部测试。

### 任务 2：安全写入、备份与回滚

- 扩展测试，覆盖原子写入、生成 legacy UUID、app-server ID 映射、备份保留策略、验证失败自动回滚和一键回滚。
- 确认新增测试失败。
- 在 `core.py` 实现恢复事务、备份和回滚。
- 运行全部测试。

### 任务 3：Windows 进程保护与中文界面

- 添加进程识别和自检测试，确认失败。
- 实现 `app.py` 与 `main.py`：扫描、项目勾选、恢复、回滚、日志提示和 `--self-test`。
- 运行测试、语法检查和 Tkinter 启动检查。

### 任务 4：打包与交付

- 使用 PyInstaller `--onefile --windowed` 构建 `Codex项目恢复工具.exe`。
- 运行打包 EXE 的 `--self-test`，核对报告文件和恢复结果。
- 启动 EXE 数秒验证窗口保持运行，然后关闭测试进程。
- 将 EXE 和简短使用说明复制到 `outputs/codex-project-restorer/`。
- 检查 Git 差异、运行完整测试并提交最终版本。

## 重点验收

- 历史“当前示例项目”不会覆盖或重复当前项目。
- 项目名称大小写或首尾空格变化仍能正确识别重复。
- 同一路径使用不同写法时仍能正确识别重复。
- JSON 损坏、数据库表缺失、项目路径不存在时不会写入状态。
- 恢复、再次恢复、回滚后均只保留一次可用备份。
