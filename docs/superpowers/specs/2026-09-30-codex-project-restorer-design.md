# Codex 项目恢复工具设计

## 目标

制作一个可双击运行的 Windows EXE。它从 Codex 本机数据库识别历史项目，对比当前侧边栏项目索引，让用户勾选并恢复缺失项目，同时确保当前 Codex 中已有的项目始终优先且不被覆盖。

## 用户流程

1. 用户完全退出 Codex。
2. 双击 `Codex项目恢复工具.exe`。
3. 点击“扫描项目”。程序读取 `%USERPROFILE%\.codex\state_5.sqlite` 和 `.codex-global-state.json`。
4. 列表显示：缺失项目、已存在项目、路径不存在项目。默认只勾选可安全恢复的缺失项目。
5. 用户点击“恢复勾选项目”。程序再次检查 Codex 未运行，再创建完整备份并写入状态文件。
6. 程序重新读取状态文件，验证项目名称、ID、路径及顺序；验证成功后仅保留最近一次备份，并提示重新启动 Codex。
7. 如需撤销，用户退出 Codex 后点击“一键回滚”，恢复最近一次备份。

## 合并规则

- 当前 `.codex-global-state.json` 中的项目是权威数据。
- 名称比较忽略大小写及首尾空格；名称相同即视为重复，即使路径不同也保留当前项目并跳过历史项目。
- 路径规范化后相同也视为重复，保留当前项目。
- 只新增当前项目列表中不存在、且至少一个根目录仍存在的历史项目。
- 不修改现有项目的名称、ID、路径、创建时间、更新时间和排序。
- 新恢复项目按历史数据库中的 `position` 追加到现有项目之后。
- 不删除、移动或改写任何项目文件夹。

## 数据来源与写入范围

只读来源：

- `%USERPROFILE%\.codex\state_5.sqlite` 的 `projects` 与 `project_roots` 表。
- `%USERPROFILE%\.codex\.codex-global-state.json` 的当前项目数据。

唯一写入目标：

- `%USERPROFILE%\.codex\.codex-global-state.json`。

程序更新 `local-projects`、`project-order` 以及已有结构需要的项目 ID 映射。其他字段原样保留。写入采用同目录临时文件、JSON 复读校验和原子替换。

## 安全与备份

- 检测到 Codex/ChatGPT Codex 相关进程时，允许扫描但禁止恢复和回滚，并明确提示用户完全退出 Codex。
- 每次写入前，将全局状态文件及其 `.bak`、`state_5.sqlite`、`-wal`、`-shm`（存在时）复制到带时间戳的备份目录。
- 写入或验证失败时立即自动恢复本次备份。
- 成功后删除更旧备份，只保留最近一次完整备份。
- 回滚成功后保留被替换前的状态副本，避免回滚操作本身不可逆。

## 架构

使用 Python 标准库和 Tkinter，打包为单文件、无控制台窗口的 EXE。模块保持精简：

- `core.py`：读取数据库和状态、计算恢复候选、合并、备份、写入、验证及回滚。
- `app.py`：中文 Tkinter 界面、项目勾选列表、状态提示和按钮行为。
- `main.py`：程序入口及隐藏的 `--self-test` 模式。
- `tests/test_core.py`：使用临时目录和测试数据库覆盖合并、备份、原子写入、验证与回滚。

不引入网络、遥测、管理员权限或第三方运行时依赖。PyInstaller 只在构建阶段使用。

## 错误处理

- 找不到 Codex 状态目录、数据库或状态文件：停止并显示准确路径。
- JSON 损坏或数据库结构不兼容：只读失败，不创建或覆盖任何状态文件。
- 历史项目路径不存在：显示为不可恢复，默认不勾选。
- 同名或同路径冲突：显示“已存在，保留当前 Codex 项目”。
- Codex 正在运行：禁止写入。
- 备份、写入或复读验证任一步失败：自动回滚并显示日志位置。

## 验收标准

- 双击 EXE 可打开中文窗口，无命令行窗口、无需安装 Python。
- 能从真实 Codex 数据库扫描出历史项目。
- 当前“当前示例项目”等同名项目不会被历史记录覆盖或重复添加。
- 只恢复用户勾选、路径存在且当前缺失的项目。
- 恢复前有完整备份，成功后仅保留最近一次备份。
- 可在 Codex 关闭时一键回滚。
- 自动化测试通过，打包后的 EXE 自检通过，并完成窗口启动冒烟测试。
